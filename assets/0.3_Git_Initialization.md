## 8. Feature-Branch Strategy

The project uses a feature/work-branch strategy rather than making all development changes directly on `main`.

A typical branch can represent a focused unit of work, for example:

```text
feature/frontend-foundation
feature/backend-api
feature/stock-data
feature/model-development
feature/prediction-workflow
```

The exact branch name should describe the work being performed.

For small project-foundation changes, direct work on `main` may be used where appropriate. As the application grows, feature branches and pull requests should be preferred for isolated development work.

## 9. `.gitignore`

A `.gitignore` file was created to prevent generated files, local environments, secrets, caches, and other non-source artifacts from being committed unnecessarily.

Important examples include:

```text
.venv/
__pycache__/
*.pyc
.env
node_modules/
dist/
build/
.ipynb_checkpoints/
```

The exact `.gitignore` should evolve as additional tools and frameworks are introduced.

---

## 10. Environment Configuration

A template environment file was created:

```text
.env.example
```

It documents the expected environment variables without containing real secrets.

The current template includes configuration areas such as:

```env
MARKET_DATA_API_KEY=
MARKET_DATA_BASE_URL=

DATABASE_URL=

MODEL_PATH=

ENVIRONMENT=development
```

Actual secret values must remain local and must never be committed to Git.

---

## 11. `.env` Protection

The actual:

```text
.env
```

file is ignored by Git.

This prevents local credentials, API keys, database credentials, and other environment-specific secrets from being accidentally committed to the repository.

The rule is:

```text
.env.example  → committed
.env          → ignored
```

## Recommended Git Commands

### Check repository status

```bash
git status
```

### View commit history

```bash
git log --oneline --decorate --graph -10
```

### Check remote

```bash
git remote -v
```

### Check current branch

```bash
git branch
```

### Create a feature branch

```bash
git switch -c feature/<short-description>
```

### Stage changes

```bash
git add .
```

### Commit changes

```bash
git commit -m "type: describe the change"
```

### Push a feature branch

```bash
git push -u origin feature/<short-description>
```

### Push `main`

```bash
git push origin main
```
