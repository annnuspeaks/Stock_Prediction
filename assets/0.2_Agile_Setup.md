# 0.2 Agile Setup

This document defines the lightweight Agile approach used for Nexora.
The existing Master Checklist is the product backlog and source of truth,
so this setup does not create a duplicate backlog.

## Product Backlog

- Use the existing Master Checklist as the product backlog.
- Treat the existing major phases/work areas as epics.
- Break only the current and near-term work into actionable user
  stories/tasks.
- Avoid creating unnecessary task-level detail far in advance.

## Definition of Done

The existing Definition of Done in the Master Checklist is used rather
than creating a duplicate Definition of Done.

## Sprint Approach

- **Sprint duration:** flexible and practical rather than a rigid weekly
  constraint.
- Finish logical, testable chunks and move forward.
- Select the highest-priority next work based on the current backlog and
  dependencies.

## Agile Activities

### Sprint Planning

Select the highest-priority next work and define the logical chunk to be
completed.

### Development

Implement the selected work incrementally while keeping changes focused.

### Testing

Verify that completed work functions as expected before considering the
chunk complete.

### Documentation

Update the relevant project documentation as implementation decisions and
completed work change the project state.

### Sprint Review / Demo

Review and verify completed work and confirm that the expected outcome is
working.

### Retrospective

Briefly record what worked, what did not work, and what should change in
the next iteration.

### Backlog Refinement

Keep the Master Checklist aligned with completed work, current priorities,
and meaningful scope changes.

## Blockers and Issues

Track meaningful blockers and issues only. Avoid creating administrative
overhead for minor development interruptions.

## Scope Changes

Use the existing **Important Project Decisions Log** for meaningful scope
changes rather than creating a duplicate tracking system.

## Agile Cycle

```text
Planning
   ↓
Development
   ↓
Testing
   ↓
Documentation
   ↓
Review / Demo
   ↓
Retrospective
   ↓
Backlog Refinement
```
